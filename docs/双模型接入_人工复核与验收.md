# 泠弦智谱｜`develop-x` 双模型接入说明（2026-10-18）

本修改基于成员提供的 `LingXian_AI-develop.zip`，**不替换团队原有 `develop` 分支**。模型为两阶段，各自权重 **不能互换**。

## 1. 当前实现与边界

- Stage1：`backend/service/yolo_infer.py`，加载 `backend/models/best.pt`，**仅用于识别减字区域**，应是名称为 `jianzi` 的单类别 YOLO 模型。按重叠切片（768、步长600、输入960）执行检测，丢弃内部切片边界截断框，再进行全图 NMS；输出归一化框与定位置信度。
- Stage2：`backend/service/stage2_reader.py`，加载 `backend/models/stage2_best.pth`，使用多头 ResNet18 分别给出 `rh/string/lh/hui_base/hui_frac/mod/tone/strings` 八个字段的 Top-3 备选。**不能理解为完整指法或谱理的自动解释**。
- 格式化：`backend/service/attribute_parser.py` 只显示上述**显式属性**，`NA` 为“未明写”，`OTHER` 为“稀有/未识别”。不会自动补全继承弦序、徽位、走手目标或简谱节奏。
- 整谱：`POST /api/sheet/upload` 返回框、字段备选、人工复核提示；默认 `U`，只能**用户人工确认后**变 `A`；可移动/添加/删除框、修改字段、输入经知识库校验的完整 class_key、保存修订与导出结果。
- 单字：`POST /api/char/predict` 现在返回上述八字段候选；如指定 `engine=qwen` 仍可显式使用原阿里云接口（须有密钥）。不再偷偷回退固定假数据。
- 句读：保留原 `/api/judou/segment`，但前端**不自动调用**；只有人工确认的、完整且能够对应知识库的 class_key 才可提交。后端的旧句读兜底依然可能产生 `source=fake`，前端会拦截不作为真实结果展示。正式论文不能写成已实现真实准确率的句读模型。
- 模型不可用：明确提示并允许人工画框，不出现凭空绘制的12个假框。

## 4. 真实端到端验收的建议清单

1. **正确权重**：两个模型都显示可用，文件名、哈希与训练证据包一致；没放权重时只显示“不支持/需手动”，不展示假结果。
2. **定位**：上传《仙翁操》后叠框位置与原始图片吻合，画布缩放和鼠标点击不漂移；人工补框、移动、删框可用。
3. **候选**：选中检测框，显示八字段 Top-3；`string=NA` 时不展示虚假的固定弦号；分别修改右手/徽位等字段，右侧释义跟着刷新。
4. **人工确认**：AI 新框默认 `U`；点击确认才变 `A`；修改框位置后自动回到 `U`，需重新识别并复核。人工确认存在本地 `backend/data/corrections.json`。
5. **知识库**：手动输入已有的 `class_key`（如 `ming_10_gou_4`），验证能查到原有知识库释义；单纯的属性组合不被自动冒充已收录完整减字。
6. **句读**：对未确认属性不自动运行；若旧句读服务返回 `source=fake`，不要将固定间隔标签宣传为 AI 打谱效果。
7. **真实性**：模型输出字段没有经过人工确认时，应显示“候选”，而不是“已识别完成”。

### 最重要的现阶段限制

前一轮《仙翁操》整页 YOLO 独立测试原始结果为 23 TP / 17 FP / 16 FN；使用裁剪后的 Stage2 再预测，真正同时定位且右手+弦序正确为 8/39（20.51%）。候选 Top-3 能帮助人工选择，但**这不是高准确率的全自动减字谱释读**。切片边缘过滤曾有离线 CSV 模拟改善，需将本次网站真实运行结果与专家真值再次比对，不能直接当成已验收改进。
