# V1版本整体方案（不做本地GPU训练）

> 方案：**Google Colab完成训练得到权重文件 → 下载权重放到本项目`backend/models/`目录 → 后端本地加载权重推理，实现完整功能；推理阶段不需要GPU，CPU可以跑。**

V1目标功能：

1. 减字识别（单字图片识别、整谱打谱图片检测识别）
2. 乐理解析（parser + jianzipu_lib.json）
3. 节奏划分（智能句读C/S/L/E/U）
4. 前后端整套可演示交付

> 关键点：**训练在Colab（谷歌GPU）；推理（项目运行）在本地电脑CPU即可。训练和推理硬件可以分开。**

## V1完整工作流

### 阶段1：单减字分类模型（ResNet18）

1. 数据集整理：`data/dataset`，文件夹名 = `class_registry.csv`的`class_key`，把裁剪好的单字图片按类别分文件夹；
2. 将数据集上传Google网盘；
3. 打开项目内 `scripts/train_colab.ipynb`，在Colab运行：挂载网盘、读取数据集、迁移学习训练ResNet18；
4. 训练完成导出权重文件 `resnet18_qin.pth`，以及id‑class_key映射表；
5. **下载权重到本机，放入 `backend/models/`**；
6. 修改 `service/classifier.py`，加载这个`.pth`权重，替换现在的假模型； ✅ 此时：`/api/char/predict`单字识别、`/api/sheet/upload`整谱打谱识别变为真实识别。

> 注意：detector（整谱图片定位减字框）V1仍然保留假模型；detector属于目标检测，训练成本更高，V1优先保证**单字分类可用**。

### 阶段2：智能句读‑序列模型（节奏划分）

> 句读训练依赖modules算法模块，必须先把modules下的算法代码实现完成（feature_extractor / rules / features / fusion / decision）

1. 准备已经人工标注停顿标签(C/S/L/E)的减字乐谱文本数据集；
2. Colab或本地CPU运行modules算法，批量输入乐谱，计算得到特征：`z_i, Δz_i, q_i`，输出样本文件`sequence_samples.pkl`；
3. 把pkl样本上传Colab，运行 `scripts/train_sequence.ipynb`，训练两套模型：baseline（逻辑回归）+ 轻量Transformer；
4. 训练完毕，下载两套模型权重，放入`backend/models/`；
5. 修改 `api/judou.py`：删除现在“4字S、8字E”的假逻辑，调用modules整套算法+加载权重做推理； ✅ 此时：`/api/judou/segment`实现真正古琴谱上下文节奏划分，输出C/S/L/E/U标签。

### 阶段3：本地运行整套项目（**不再需要网络/谷歌，纯本地**）

1. 后端启动，自动加载models目录下两份权重；

2. 启动前端；

3. 完整能力：单减字识别解析、整谱打谱上传识别、智能句读节奏划分、人工复核接口；

   > 推理仅CPU就可以跑通演示，不需要显卡。

## 风险提示

1. Colab会话超时问题：长时间不操作会释放GPU，训练要一次性跑完；
2. 权重下载：训练结束务必把`.pth`下载回本地，Colab云端环境销毁后文件全部丢失；
3. id与class_key映射：训练时必须严格对齐`class_registry.csv`顺序，否则识别结果全部错乱。
